# 固件二进制识别实测与改进

用户已授权：对两份指定固件实扫，直接扩库、修正识别并重扫对比；子 agent 使用 Luna。

1. 保存原版源码快照与扫描结果。Allwinner 使用完整 CLI；2.2 GiB 原始 ext4 使用同一产品 AndroidSystemScanner、Ext4Reader 和 CLI 去重，以只读 mmap 控制内存。前后保持相同入口。
2. 修正证据语义：Android 基线、HAL 接口、SONAME/符号 ABI、编译器/Go 运行时、API 下界均不能直接成为宿主组件的精确发布版本。保存为属性或未知；保留开发版本完整标识。
3. 扩充带官方来源的规则库，以明确 banner 或真实已定义的符号组合识别第三方组件；排除仅导入符号、协议版本及其他库的字符串。
4. 对简单版本返回函数做有边界的静态指令解析。未知指令或控制流拒绝，绝不执行目标文件。
5. 接入 Android 原生文件及 APK 内嵌原生库扫描，保留文件位置和多版本；调整读取和目录覆盖，避免截断或仅保留首个依赖。
6. 运行针对性行为回归及完整单元测试，重扫两份输入。将全量候选覆盖、独立核验子集的正确性、仍未知的版本分别报告。

验收依据：可复现的 JSON/SBOM、真实文件证据及前后差异；规则条数和非空版本字段不构成准确率。仅这两份固件不能证明跨厂商泛化率或完整召回率。

研究方向：分层证据与归属追溯、显式冲突与厂商分支状态；函数级版本敏感特征需要独立构建语料和留出评估，暂不宣称已完成。
