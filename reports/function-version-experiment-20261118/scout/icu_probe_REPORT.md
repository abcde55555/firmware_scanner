# ICU static getter probe handoff

The opt-in probe in `experiments/function_versions/icu_probe.py` accepts one deliberately narrow path: ELF64 little-endian AArch64, defined exported `u_getVersion[_N]`, exactly `ADRP x1; ADD x1,x1,#imm (unshifted); B`, a read-only dotted string addressed by that pair, and an exact four-instruction AArch64 PLT entry whose decoded `ADRP + LDR displacement` equals that entry's `.rela.plt` `r_offset`. The PLT `ADD` must agree with the LDR displacement, and `BR x17` must use the register loaded by `LDR`. The matching same-image `u_versionFromString[_N]` must be defined and have a decoded `RET`. Each parsed component must fit `uint8` (0..255). Everything else is rejected.

The real system input is `/home/kali/Desktop/work/project/vulnscan/mnt_system/system/lib64/arm64/libicuuc.so` (SHA-256 is recorded in `icu_probe_results.json`). It produced **1 verified match: ICU 76.1**. Evidence records getter VA `0x1094e8`, instructions `ADRP x1,#0x40000; ADD x1,x1,#0x652; B 0x1ca370`, string VA `0x40652`, and helper `u_versionFromString_76` at VA `0x1090d0`. The PLT entry at `0x1ca370` resolves through GOT slot `0x1e3480`, matching the relocation's `r_offset`; the result JSON also retains the exact getter disassembly, branch target, helper return, and source links.

All five in-memory negative cases rejected: Unicode-only getter, relocation redirected to `u_getUnicodeVersion_76`, PLT LDR changed to a different GOT slot, shifted getter ADD, and version component `999` exceeding `uint8`. The system ARM32 ICU input returned zero matches by architecture rejection.

ICU's release-76-1 implementation in [`putil.cpp`](https://github.com/unicode-org/icu/blob/release-76-1/icu4c/source/common/putil.cpp) calls `u_versionFromString(versionArray, U_ICU_VERSION)` from `u_getVersion`. The API declaration/documentation in [`uversion.h`](https://github.com/unicode-org/icu/blob/release-76-1/icu4c/source/common/unicode/uversion.h) describes dotted-decimal parsing into the bounded `UVersionInfo` fields. Source URLs are unanchored so the report does not assert unchecked line numbers.

Explicitly unsupported: ARM32/Thumb (including veneer and ARM PLT layouts), Allwinner's complex/inline ICU parsing path, AArch64 PLT variants with different instruction/register layouts, shifted or otherwise unhandled address calculations, non-PLT direct calls, other ISAs/ELF classes/endianness, and getters whose string/helper/return chain does not match the exact accepted form. The Allwinner path is not claimed as a tested negative in this run. No ELF was loaded or executed, and no firmware bytes were changed; mutations were in-memory only.
